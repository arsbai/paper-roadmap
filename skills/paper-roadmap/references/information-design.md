# 文字取舍、logo 与方法图示

用于整篇技术路线的内容压缩、图示选择和字号统一。依据八张城市研究参考图及实际制图中的删改反馈归纳；不是固定四分区模板。参考索引见 [八张城市研究图](../assets/urban-methods/index.md)。

## 保留方法骨架，展开关键转换

整篇总览优先回答：什么数据、怎样形成研究变量、用什么方法比较、得到什么产物。保留能定位方法的名称，再用一个有含义的图示表现关键转换。不把正文步骤缩成许多小字框。

每条候选文字先判断：删掉后是否会误认数据、比较对象、时间/空间单位、关键方法或输出？若会，保留或用图示接住；若不会，再看是否只是重复、实施细节或解释性句子。方法完整不等于罗列全部参数。

| 内容 | 总览图的处理 | 适合的表达 |
|---|---|---|
| 核心方法和创新环节 | 优先保留，必要时保留区别于常规方法的限定词 | 方法短名＋过程示意，而非算法名列表 |
| 数据来源、时间与分析单元 | 保留识别研究设计所需的信息，避免重复 | 两期照片、来源标识、点/格网/街段符号和短标签 |
| 数据到变量的关键转换 | 必须让读者看见转换，详略随图的范围决定 | 配对影像→更新；独立影像→活动；原图→分割→特征；叠层→聚合 |
| 结果及下游接收的产物 | 保留产物名；核心产物可用真实小图 | 匹配样本、活动差值地图、词云、效应区间 |
| 决定比较对象或估计含义的条件 | 保留最少必要的限定，或放在紧邻图注 | 基期变量、处理/对照、精确分层、变化差及必要单位 |
| 全变量表、普通采集/清洗/实现参数 | 通常移到正文或材料；若是本研究创新或会改变样本定义则保留 | 分组图标＋代表性指标；有研究含义的筛选可用简洁筛选示意 |
| 重复解释、完整句子、运行及核验要求 | 从总览移出，原方法和记录仍保留 | 不另加“请报告”“保持原配对”“逐项核查”等图中文字 |

不以每框限几个字作为机械规则。方法展开图可以保留确有解释作用的参数、公式和训练设置；整篇框架不默认复刻这些细节。整篇图中的核心方法名可以突出显示，图例、组别、时间和单位不能因追求“只留方法”而丢失。

## 从初稿到认可稿的取舍

以下例子说明图面取舍；不把某项研究的分析选择推广为其他论文的规则，也不把从图面删除等同于从分析中取消。

| 初稿或中间稿 | 更合适的处理 | 可迁移的判断 |
|---|---|---|
| 协变量总数、逐项变量及追加条件挤在同一行 | 用基期变量分组和必要指标接住，完整变量定义留正文 | 数量清单不能替代变量来源与作用 |
| 报告保留率、报告ESS、冻结配对等操作提醒 | 移出图面，保留实施记录 | 核验记录不默认属于研究总览 |
| 对齐、计数核验等常规操作整排展开，再列分析表字段 | 根据当前任务压缩为测量结构；决定样本定义的筛选仍按研究含义保留 | 不把每项常规处理画成同等重要的研究步骤 |
| 原始描述后再列对象、动作、方向等重框 | 若没有解释实际转换，用原始描述连接真正的编码或下游分析 | 多个图标仍可能只是重复文字 |
| 地图下长段方法及单位说明 | 按图的用途保留必要含义，可用点位与邻域符号表达空间层次，统计细节留正文 | 总览表达任务，方法展开图再解释内部计算 |
| 泛用模型文字条或机器人图标 | 实际模型logo＋识别任务短标签，与输入和输出相接 | 模型身份与执行任务分别由logo和短标签承担 |

用户明确删掉的文字、箭头和模块，在同一任务后续修订中不能自动恢复。研究方法名通常应保留；若用户要求其在总览中改成更简洁的任务标签，把对应关系保存在内容记录中，不擅自加回图面。

## 选择 logo、图标、过程示意或真实小图

| 读者需要知道什么 | 选择 | 例子及边界 |
|---|---|---|
| 用了哪个平台、模型或特定软件 | 真实logo＋必要短名/任务 | 千问、Kimi、GPT、微博、百度等；只放当前研究确实涉及者 |
| 研究的对象、行为或变量组是什么 | 通用概念图标＋类别名 | 人物动作、街道、绿树、边界、POI；不要用机器人代替所有方法 |
| 关键方法怎样把输入变成输出 | 过程示意＋方法短名 | 匹配点及配对线、两组双期变化、影像分割、格网到街道的聚合 |
| 真实样本或分析产物是什么样 | 有来源的照片、地图、分割图或结果小图 | 同点前后街景、实测地图和实际词云；不制作伪结果 |
| 一个准确、很短的条件/标签 | 直接文字 | 年份、单位、组别、必要阈值；不强配装饰图标 |

**logo回答“谁/哪里”，过程示意回答“怎样”。** 一排logo不能代替方法结构，也不表示所有候选模型都进入最终批量分析。若模型比较与最终选用不同，依据材料显示角色；不能凭logo顺序、大小或勾号暗示已做的性能比较。仅在供应商/软件身份有信息价值时使用软件logo，普通脚本不自动加入Python或R标识。

需要logo时实际从网上找，不因缺少本地图标就自画近似商标：先查官方品牌页、官方网站资源或官方代码仓库，再考虑来源明确的维护型图标库。核对具体产品与标志版本；不要为历史研究自动换成新模型。优先矢量或清晰透明图，保持比例和品牌允许的配色，按视觉重量协调大小，离线嵌入成图。记录来源链接及文件，不把“网上可下载”当作任意复用许可。

可从实际使用产品的官方品牌页、官网或官方仓库寻找标识，例如 [Kimi品牌页](https://www.kimi.com/resources/kimi-brand)、[Qwen官方组织](https://github.com/QwenLM)；微博等数据平台也可查官方标识规范。入口及许可使用时核对，页面打不开或未取得文件时不声称已经下载或核实。产品家族、具体模型和厂商身份不要混用。

这些只是通用例子，不因此把微博或任何模型加入未使用它们的研究。参考图中的商标也不能直接截出来当作新图的通用素材。

## 三档字号是统一样式，不是每个框各自适配

先按语义设最多三档，例如模块标题、方法/类别名、必要指标/条件；两档足够时不补第三档。同级文字在全图共享字号，不能某一框放不下就另缩成第四档。编号、公式上下标及可编辑图例也纳入这套字号。真实嵌入结果图不为凑字号而改写，其必要标签仍须在整图展示时可读。

字体家族尽量统一；同档可用既定粗细区分，但字体、斜体、加粗不能随框任意变化。品牌logo中的字形保持品牌身份，不用于派生正文样式。只要求改字号时，原有粗细、文案和位置锁定。当前图的数值字号不是以后所有图的固定标准。

压缩文字后应利用释放的空间放大方法图示和文字、拉开内部间距、重新居中标签及引线。不能文字变少而仍保留原来为长段落预留的空框。局部“其他不变”任务只做授权范围内必要调整；不要借机会重排全图。

最后用整图适宽预览比较：读者能否沿着图看见数据→转换→产物，还是仍需逐框读句子？同级字号是否一致？删掉冗余后方法是否反而更清楚？再看密集局部，不能只查字号数量。
