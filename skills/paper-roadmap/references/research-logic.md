# 研究逻辑与内容状态

## 从证据构建图

证据采用用户最新的明确修正、当前认可稿、当前论文方法/结果及必要补充。旧提纲、历史图和历史助手推测只作线索。冲突若影响科学含义，记录冲突并核实；不能把某个文献中常用的方法当作本研究已实施的方法。

逐节点记录：它回答什么、输入是什么、采用何种处理/分析、产生什么输出，证据在何处。保留图上确有价值的样本量、时间范围、关键阈值和方法名，来源用 PDF 页码、章节、图号、表号或用户具体补充定位。区分计划执行与已执行的步骤。

不需要在每幅图中强制画出“问题—数据—方法—结果”四个框；它们是阅读材料的观察角度。系统综述、实验、质性、理论及计算论文可以有完全不同的图。

## 图的范围与信息取舍

先确定图的用途。整篇研究总览组织研究任务、主要转换与产物衔接，不追求覆盖每个操作；局部方法图可以展开该方法的控制条件、中间状态与验证。概念关系图表达构念及假设，不自动转换成执行流程。必要时在总览内局部展开关键创新，保持整体与细节的层次清楚。

为过程或分析模块回答：它解决什么问题，接收什么对象，完成什么关键转换，交出什么产物。下游应接住确切产物，例如前一步形成指标矩阵，后一步以该矩阵的特征建模。只列模型名称往往不足以说明研究如何推进；这些问题用于提炼，不要求每框机械写出四个字段。概念或理论节点按构念、假设及关系组织，不强行赋予操作和输入输出。

图面信息按作用取舍：

- 保留界定对象、变量含义、处理/对照条件、多尺度比较、筛选与择优、关键汇合及创新机制的信息。决定研究设计的阈值、时间窗口或公式可以保留。
- 常规归一化、损失函数、调参、早停和完整提示词等通常移入正文或配套说明；若它们是本图要解释的方法重点、决定比较条件或用户明确要求，则保留必要部分。不要机械删除所有参数或公式。
- 用短标签及结构承担关系：多个尺度并列、指标组成用矩阵、路径机制用小型关系图、转换用前后对照。示意只表达有依据的概念，不编造真实样本、频率或结果。
- 核验用的全部细节与图面的必要信息分开保存。初次提炼可以删去次要说明；内容已锁定时仍遵守追改协议，不能以精简为由改写。

压缩后从原文再沿“样本 → 筛选/分组/尺度选择 → 模型输入 → 输出范围”回查一次。尤其保留先比较全部组合、再选定范围、最后在所选模型上解释的转折；不能将后续解释写得像覆盖所有组合。图与自身内容模型一致不能发现两者共同遗漏的步骤。

## 容易画错的关系

| 材料含义 | 图中表达 |
|---|---|
| 同一批样本完成共同前处理，再进行两项独立分析 | 前处理之后分叉，不能凭版面把两项分析串联 |
| 随机分组或处理组与对照组 | 分支和并排对照；时间点可沿共同时间轴表达 |
| 问卷和访谈分别采集，解释时整合 | 两条路径，仅在实际整合环节汇合 |
| 规则分类与聚类均出现 | 保留各自依据；不能用“聚类”统称阈值分类 |
| 每个结果各训练模型，再比较模型家族 | 区分结果数、模型家族数和最终保留模型数 |
| 全组合拟合后选最优范围，再比较变量影响或曲线 | 保留选优步骤及后续分析范围；不能把全组合比较与选优后解释混写 |
| 多个尺度分别建模 | 并列或分组比较，不能画成连续训练步骤 |
| 两项独立结果在解释时共同支持分区或策略 | 表达解释性综合，区别于算法输入或计算汇合；不要为连接全部框而新增数据依赖 |
| 方法输出需要与专家判断或真实样本对照 | 表达验证关系；多项独立检验不因排列位置而被画成先后步骤 |
| 相关或描述性空间对应 | 用中性关系标签，不能画成已证实的因果链 |
| 构念之间的理论假设 | 区分概念关系图与操作流程，不自动改成先后步骤 |
| 图中有空位或空框 | 核对是否遗漏；无证据时删空框或重排，不能补造分析 |

若分支输出需要在同一个结果组展示，可并列放入组内；这不自动表示它们在计算上汇合。虚线、颜色和箭头样式只有在含义必要时增加，保持图例简短。

原文缺参数、正文与图注命名冲突、输入年份或聚类细节不明确时，记录到 `open_questions`。采用有证据的中性表述或限定覆盖范围，不补造参数；也不把原文的信息缺口记为技能已失败。记录实测、模拟、预测和建议等状态，不能混成已经验证的结果。

## 可维护的内容记录

推荐结构如下。字段可按任务裁减；稳定 ID 和内容/几何分离比具体格式重要。

```json
{
  "paper": {"file": "paper.pdf", "scope": "methods and supplied corrections"},
  "figure": {"scope": "whole-study", "focus": "研究任务及产物衔接"},
  "languages": ["zh", "en"],
  "nodes": [
    {"id": "clean", "level": 2,
     "labels": {"zh": "数据清理", "en": "Data cleaning"},
     "input": "原始样本", "operation": "按原文标准筛选", "output": "有效样本集",
     "source": "Methods 2.2, PDF p.4", "status": "implemented"},
    {"id": "analysis-a", "level": 2,
     "labels": {"zh": "分析甲", "en": "Analysis A"},
     "input": "有效样本集", "output": "分析甲结果",
     "source": "Methods 2.3, PDF p.5", "status": "implemented"}
  ],
  "edges": [
    {"id": "e1", "from": "clean", "to": "analysis-a", "kind": "data-flow",
     "carries": "有效样本集",
     "source": "Methods 2.3, PDF p.5"}
  ],
  "deleted_ids": [],
  "open_questions": [],
  "revision": {"baseline": null, "mode": "draft", "authorized_changes": []}
}
```

`level` 指视觉层级，只允许 1–3，并非研究流程只能三步。可把同一层级的多个流程节点放在任意有依据的位置。标签用稳定 ID 区分标题、正文和说明；若一个节点有多段文字，可增加 `labels` 子项 ID。

布局坐标、颜色、连线转折和语言换行放在独立布局结构中。换行不应改动内容来源或关系。双语版本共享节点、数字与边集合；对不同语言补足必要语法不能增加研究步骤。

采用图片时，另记录其文件、来源、所属节点和角色（输入、处理中间状态、输出或验证等）。在设计记录中保存目标展示场景/宽度及实际缩览条件。研究字段、素材与几何分开维护；已有的轻量记录可直接扩展，无需为小图建立冗长表单。

## 追改协议

1. 找到用户认可的最近版本及当前删除状态，不自动选择文件日期最晚的草稿。
2. 将反馈拆成明确内容改动和视觉改动。文字不变时保留各标签的规范化文本；关系不变时比较 `from/to/kind`。
3. 将本轮授权改动加入记录。例如删除某一参数行应在对应标签 ID 留下删除记录，而不是只在图片上遮挡。
4. 改动完成后，核对授权列表之外的文本、数字、节点、关系差异为零；也核对未指定区域及其图像/颜色没有意外改变。
5. 显式删除后的新版本成为下轮基线。不可因为重新生成整图而恢复旧内容。

文字差异工具仅作辅助：同义改写仍是文字改动；图面文字不变也不能证明箭头和语义未变。用户要求仅重画一部分时，可另交局部 SVG，保持与整图相接的尺寸与入口/出口关系。
