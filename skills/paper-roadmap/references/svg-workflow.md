# SVG 制作与核验

## 制作约定

SVG 使用合理的 `viewBox`，明确宽高，并为有含义的节点/连接设置稳定 ID。正文用 `<text>` 和 `<tspan>`；一个标签可以多行，但不转成路径。图标与连接用分组路径/几何元素，可嵌入论文位图。无需把所有图标变成相同尺寸，应以视觉重量和重要性协调。

推荐给每个独立文字标签加 `data-label-id`。标签有独立容器时，给文字或其祖先组加 `data-container="box-id"`，并让对应框带 `id="box-id"`。例如：

```xml
<g id="node-clean">
  <rect id="box-clean" x="40" y="40" width="320" height="120" />
  <text data-label-id="clean-title" data-container="box-clean"
        x="200" y="92" text-anchor="middle" font-size="28">
    <tspan x="200">Data cleaning</tspan>
  </text>
</g>
```

不要在源码标签前后加入无意空格。英文不同单词跨 `<tspan>` 换行时，保留正常词间空格；中文换行不额外插入空格。这有利于对照同一份内容记录。

使用通用且具有目标语言字形的字体栈；检查字体替换，最终用户编辑时仍需相应字体。`<title>`/`<desc>` 可写简短主题说明，但不能偷偷加入未出现在论文中的研究内容。

交付文件不依赖远程图片、远程字体或本地绝对路径。不包含脚本、事件处理器或 `foreignObject`。SVG 图标内联为路径；本地照片编码嵌入，避免把另一个 SVG 编码成图片后丢失图标编辑能力。

## 运行渲染检查

`scripts/render_check.mjs` 需要 Node.js 和已安装的 Playwright Chromium。优先使用宿主提供的依赖加载工具；其他环境使用其已有运行时。脚本不自动安装依赖或下载浏览器。

```text
node <skill>/scripts/render_check.mjs <drawing.svg>
  --png <preview.png> --report <qa.json>
  [--modules <absolute-node_modules>] [--browser <chromium-executable>]
```

各参数在实际运行时写在同一行。路径含空格时按当前 shell 引号规则作为单个参数传入。缺依赖/浏览器时，使用环境已有替代渲染器并实际查看输出；仍不可用就明确未完成视觉核验。

追改中的文字比较：

```text
node <skill>/scripts/render_check.mjs <revised.svg>
  --png <revised.png> --report <qa.json>
  --baseline <approved.svg> --lock-text
```

`--baseline` 只比较文字，按稳定的 `data-label-id` 为主；缺稳定 ID 时按脚本报告的退化方法比较。`--lock-text` 把未保持文字的情况作为错误。若本轮授权删除或替换了文字，先依据授权列表核对这些差异，再用更新后的基线继续；不要为让检查通过掩盖或忽略未授权差异。

文字比较忽略所有 Unicode 空白，因此会将英文 `A B` 与 `AB` 视为相同，不能独立证明文案完全不变。应人工对照内容记录确认空白与词界，尤其是无稳定 ID 的历史 SVG。脚本不检测模型/边集合的语义变化；另行对照 `diagram-model.json` 的 `nodes/edges/deleted_ids`。

## 报告的含义

- 输入检查先拒绝外部资源、活动内容等不符合离线成图的输入，避免渲染过程偷偷加载网络资源。
- 硬错误包括超过三档字号和元素超出画布；公式上下标也应纳入三档字号范围。
- 文字相交、文字超出声明容器等为待检查警告。某些重叠是有意的，可在元素/祖先组加 `data-check-overlap="ignore"`，只对已确认的具体情形使用。
- 无警告并不证明没有箭头穿框、遮挡、看不清的图片、缺字、颜色问题或研究逻辑错误。工具输出保留可核查的原始信息，不能代替看图。
- 脚本不判断信息取舍、图文融合、产物衔接或最终展示尺寸下的可读性。SVG 与内容模型一致也不是与原文科学含义一致的充分证据。

## 必须看什么

1. 按目标展示宽度看整图：研究主线是否突出，模块是否接住上游产物，分支与汇合是否准确，是否只有最多三级层级。正文、关键标签及原图必要细节都应能读；不能只在原始大画布或放大局部时查看。未指定用途时，自行选择合理的整图适宽预览，记录实际查看条件，不预设固定像素值。
2. 放大密集区域：文字是否越框/裁切，数字和英文术语是否完整，字形是否缺失；箭头是否穿过文字或指错框。
3. 对照素材与示意：图标是否表达当前概念和动作，线宽是否协调，原图是否融入所属步骤并承担明确角色，图例/单位/比例尺及实测或模拟身份是否保留。方法示意是否有明确身份、组别和必要条件，且能与实测结果区分。检查图形与文字的相互遮挡，尤其是点位、人物、连线与邻近标签；仅检查文字相交不够。仅在图旁陈列原图而不帮助理解步骤，应重新组织。
4. 对照内容：从原文回查方法、关键数字、节点与关系，尤其是筛选、择优、分组、尺度变化及后续分析的适用范围；区分数据输入、解释性综合和验证。另查图面是否堆积了应移到说明的常规细节；双语结构与数字对应。
5. 追改时比较基线：授权之外的文字和关系不变，局部修改未误改其他区域，删除项未恢复。

每个语言版本都要渲染，不可只看英文后推断中文没有溢出。需要时另生成细节裁片供检查。只有已观察的检查才能在交付说明中称为完成。

测试记录区分自动检查、对原文的内容回查、实际视觉查看和用户编辑器兼容性。记录有代表性的查看条件、发现的问题及未完成项即可；自动报告的原始状态保留，不用“全部通过”覆盖其范围限制。浏览器渲染和可编辑的 SVG 结构成立，不代表已在用户的排版或演示软件中实测。
